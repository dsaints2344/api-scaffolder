# Go

## Defaults
| Concern | Default |
|---|---|
| Go version | installed (`go version`) |
| HTTP | standard `net/http` with method and path patterns in `ServeMux`; chi only if named |
| Data | PostgreSQL with `pgx`, queries generated by `sqlc` |
| Validation | `go-playground/validator` |
| Config / logging | environment variables, `log/slog` (JSON handler) |
| Tests | standard `testing`, `httptest`, Testcontainers for Go for the database |
| Architecture tests | go-arch-lint |

## Commands
```bash
go mod init <module-path>
mkdir -p cmd/<service> internal/{domain,application,infrastructure,transport/http}
```

## Mapping layers
`cmd/<service>/main.go` is the composition root. Layers are packages under `internal/` (Clean: `domain`, `application`, `infrastructure`, `transport/http`; Hexagonal: `core/domain`, `core/ports`, `core/usecases`, `adapters/http`, `adapters/postgres`). Interfaces (ports) are declared where they are consumed, which in Go is the inner layer.

## Pattern libraries
| Pattern | Choice |
|---|---|
| CQRS / Mediator | plain generic interfaces (`CommandHandler[C, R]`, `QueryHandler[Q, R]`); no mediator library |
| Result | idiomatic `(value, error)` with sentinel and typed errors, mapped to ProblemDetails JSON in the HTTP layer |
| Outbox | outbox table in the same `pgx` transaction + a worker goroutine |
| Messaging | `segmentio/kafka-go`, `rabbitmq/amqp091-go`, or the broker's SDK |

## Architecture tests
`.go-arch-lint.yml` declaring components (one per layer) and their allowed dependencies; run `go-arch-lint check` in CI and in the verify step.

## Monorepo
One module per service under `services/<service>`, shared modules under `libs/`, and a root `go.work` listing them all.

## Verify
```bash
go build ./... && go vet ./... && go test ./... && go-arch-lint check
```
